## 1. 핵심 결론 통합

발표 스토리와 가치 선언문을 쓸 때 읽어야 하는 결론만 모았습니다.

### 시장·경쟁 (01·04)

- 이 산업은 **구매자 힘과 대체재 위협이 높고**(무료 대안 다수·전환비용 0·"그냥 유지"가 최강 대체재) **공급자 의존도도 높다**(카드 이용내역은 마이데이터 API 단일 채널 🔵).
- 진입을 정당화하는 근거 2개 — ① 경쟁 6곳 중 **미래소비반영·실행설계·근거공개 3조건 동시 충족 0곳** 🔵 ② **마이데이터 접근은 공통 자산이 아니라 상위 사업자 한정 자산**(트래픽 1위 카드고릴라가 비마이데이터 모델).
- **TAM** = 마이데이터 누적 가입 1억 7,734만 건 🔵 (고유 인원은 공개되지 않는 지표라 산출하지 않음) → **SAM** = 12개월 내 소비구조 변화 예상자(혼인 24만 건 🔵 × 2 등) → **SOM** = 혼인 Beachhead.

### 우리가 다른 지점 (02·11)

| | 체인 |
| --- | --- |
| 경쟁자 | 과거 소비 조달 → 단일 카드 매칭 → 결과 표시 · **2단계** |
| **CardFit** | 미래 의도 포착 → 시나리오 모델링 → **제약 최적화** → **결제수단 배분** · **4단계** |

경쟁자 체인에 **뒤 두 단계가 아예 없다** 🔵. 벤치마크 3사는 역할이 나뉜다 — 뱅크샐러드(현재 상태 진단) · 핀트(리밸런싱 게이트) · 토스(Decision UX).

**경쟁 재정의**: *과거 행동을 이용한 사후적 최적화 → 미래 행동을 입력받아 의사결정 전에 수행하는 **선제적** 최적화.* 차별점은 카드 개수가 아니라 **시간축과 의사결정 방식**이다.

### 이겨야 하는 조건 (03)

| 구분 | KSF |
| --- | --- |
| 🧱 Table Stakes | 1 마이데이터 접근 안정성 · 2 혜택 Rule 최신성 관리 |
| ⭐ 차별화 | **3 손실 가시화 + 근거 투명성(동기 + 신뢰)** · 4 전환율을 높이는 제안 설계 · 5 Beachhead 도달력 |

**3번이 핵심**이다 — ①"지금 카드로는 얼마를 놓치는지"를 손실로 보여주는 것(동기)과 ②그 숫자를 검증하게 하는 것(신뢰)은 **다른 문제**이고, 둘이 함께여야 "유지" 대체재를 이긴다.

### 고객과 기회 (05·06·07)

- 12명 스펙트럼(Core 5·Adjacent 3·Extreme 2·Non-user 2), 서비스 고유 7단계 여정. **완주 실패 4명** — 조민아 ③온보딩 · 신은서 ⑥실행 · 윤태호 ⑤~⑥실행 · 배정호 ②인지.
- 기회점수 **A(미래지출 자동 연결) AOS 4.0 1위**, **C(실행 완주)·F(이벤트 비종속) 3.2 공동 2위**. 보수적 모수(SAM)에서는 **C가 1위**로 역전 — **A·C 사실상 공동 1위**.
- Job 선언 6개(A~F) + 경계 3개. JTBD 인터뷰의 가장 뚜렷한 신규 발견은 **실행 마찰**이다.

### 우리가 주는 가치 (08)

Fit 검사 결과 **✅3 · 🔶2 · 🔴1** — 공동 1위 기회 **C(실행 완주)에 대응 기능이 없다.**

## 2. 가치 선언문 작성 재료

선언문에 넣을 수 있는 축을 근거 강도와 함께 정리했습니다. **골라 쓰시면 됩니다.**

| 축 | 문장 재료 | 근거 강도 | 주의 |
| --- | --- | :---: | --- |
| **시간축** | 과거 결제내역이 아니라 **앞으로 쓸 돈**을 기준으로 | 🔵 강함 | 경쟁 6곳 미래소비반영 0곳 — 가장 안전한 축 |
| **의사결정 방식** | 사후 정리가 아니라 **결정 전에** 미리 | 🔵 강함 | 11번이 "진짜 경쟁 포인트"로 지목 |
| **조합 단위** | 카드 한 장이 아니라 **조합을 배분** | 🔵 / ⚠️ | 01·02는 경쟁자가 단일 카드라 하고 **11번은 뱅크샐러드도 조합을 한다고 씀 — 문서 충돌**(3절 참고) |
| **근거 공개** | 결과만이 아니라 **계산 과정까지** 검증 가능하게 | 🔵 강함 | 민원 +88.4%가 불신의 실재를 뒷받침 |
| **손실 가시화** | 지금 조합을 유지하면 **얼마를 놓치는지** | ⚪ | KSF 3의 ①동기 — 행동을 만드는 힘 |
| **유지도 정답** | 무조건 바꾸라고 하지 않는다 | ⚪ | 신규카드 경계 pain point 해소 장치 |
| ⚠️ 실행 완주 | 계산에서 끝나지 않고 실행까지 | 🔴 | **현재 기능 없음** — 선언문에 넣으면 과장이 됨 |

**지금 08번에 들어 있는 초안**(교체 가능합니다):

> 소비가 곧 바뀔 사람에게, CardFit은 과거 결제내역이 아니라 앞으로의 지출 계획을 기준으로 카드 조합을 다시 계산해, 지금 조합을 유지할 때와 바꿀 때의 차액을 계산 근거와 함께 보여준다. 그래서 사용자는 카드사의 권유나 감이 아니라, 자기가 검증한 숫자로 결제 포트폴리오를 결정한다.

축약: *과거를 보고 카드를 고르는 게 아니라, 앞으로 쓸 돈을 기준으로 카드 조합을 다시 짠다 — 계산 근거까지 함께.*

## 3. 통합 전 해소할 충돌·미해결

| # | 항목 | 내용 |

| 🔴 1 | **뱅크샐러드가 조합을 추천하는가** | 01·02는 *"단일 카드 매칭만 있고 끝난다"* 🔵 / 11 §7은 *"뱅크샐러드도 이미 최적 카드 조합을 추천한다"* — **정면 충돌**. 2026.05 출시 보도는 *"단 한 장의 추천 카드로 사용했을 때와 비교"* 로 01·02를 지지. **선언문의 "조합" 축이 여기 걸려 있음** |
| 🔴 2 | **실행 완주(C) 공백** | 기회점수 공동 1위에 대응 기능 없음. 반면 02번 종합은 *"해지 실행을 서비스 범위로 착각하면 괴리"* 라며 범위 제한을 개선 기회로 제시 — **팀의 문서화된 입장과 기회점수가 반대 방향** |
| 🔴 3 | KPI 사각지대 | Primary가 Payment Plan Selection Rate라 "선택"까지만 측정 — 선택 후 실행 실패가 성공으로 집계됨 |
| 🟠 4 | 방어선 vs Table Stakes | 01은 데이터 운영 역량을 **방어선**이라 하고 03은 같은 것을 **Table Stakes**(경쟁우위 아님)로 분류 |
| 🟠 5 | TAM 단위 | TAM은 **건수**, SAM·SOM은 **인원** — `SOM ⊂ SAM ⊂ TAM` 포함관계가 단위 불일치로 성립하지 않음 |
| 🟠 6 | 인용 경로 122건 | 윤정 폴더 재편(날짜 폴더화·접두어 제거)으로 구경로 인용이 전부 깨짐 |
| 🟠 7 | G·T ID 정의처 | Guardrail G-01~G-06과 테스트 T-01~T-10의 유일한 정의처가 **08.19 기각 문서** — 09 PRD 착수 전 이관 필요 |
| ⬜ 8 | 팀명 | p1의 마지막 빈칸. 제출 폴더명 `팀명_CardFit_역기획프로젝트_Final` |
