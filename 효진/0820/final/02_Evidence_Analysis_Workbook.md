### 스코프 경계 — 이 프로젝트의 핵심 결정

| 하는 것 | 안 하는 것 |
| --- | --- |
| "이 카드를 해지하세요"라고 **계산 결과를 제안** | 실제 해지 절차를 **대신 처리·안내** |

## 탭 03 · KSF

### Top 5와 구분

| # | KSF | 구분 | 판단 근거 |
| :---: | --- | :---: | --- |
| 1 | 마이데이터 접근 안정성 | 🧱 Table Stakes | 없으면 계산 불성립. **기존 사업자는 이미 보유 = 경쟁우위 아님** |
| 2 | 혜택 Rule 최신성·정확성 | 🧱 Table Stakes | 후발주자도 같은 운영 비용을 감당해야 하는 진입장벽 |
| 3 | **손실 가시화 + 근거 투명성** | ⭐ 차별화 | **핵심 KSF** — 대체재("유지하기")를 이기는 유일한 힘 |
| 4 | 전환율을 높이는 제안 설계 | ⭐ 차별화 | 계산 결과 제시만으로 전환이 보장되지 않음 |
| 5 | Beachhead 도달력 | ⭐ 차별화 | 트래픽 격차를 정면으로 좁히지 않고 좁은 진입로 확보 |

### KSF 3의 구조 — 왜 둘이 함께여야 하나

| 축 | 내용 | 하나만 있으면 |
| :---: | --- | --- |
| ① 동기 | 지금 카드를 그대로 쓰면 이번 지출에서 얼마를 놓치는지 **손실로** 제시 (예: "지금 카드로는 혜택 0원, B카드로 바꾸면 8,000원 더") | "과장 광고 아니냐"는 의심 |
| ② 신뢰 | 그 격차 숫자가 진짜 계산이라는 걸 사용자가 **검증할 수 있게** 근거 공개 | "그래서 뭐가 달라지나"는 무관심 |

**"계산은 규칙 엔진, AI는 설명"** 원칙이 ②의 기술적 구현 조건이다. 단종카드 자동대체 후 혜택 불일치 민원이 이미 존재한다는 사실(🔵 → 탭10 E-02)이 ②의 필요성을 뒷받침하지만, **"유지하기"를 이기는 힘은 ①에서 나온다.**

### 자원 배분 결론

순서를 정하는 기준은 **의존성**이다. 1·2 없이는 계산이 성립하지 않으니 항상 선행한다. **3이 기존 사업자 대비 실제로 이길 수 있는 지점**이므로 핵심 KSF다. 3은 시스템 설계 초기부터 반영해야 나중에 되돌리기 어렵다.

## 탭 04 · TAM-SAM-SOM & Segment Map

### 모수 후보와 채택 판정

| 후보 지표 | 값 | 집계 기준 | TAM 채택 |
| --- | --- | --- | :---: |
| **마이데이터 가입 건수** | **1억 7,734만 건** (2025.10) 🔵 | 서비스별 가입 누계, **중복 포함** | ✅ |
| 마이데이터 이용자 수(별도 집계) | 1억 6,531만 명 (2025.05말) | 상이한 산정 기준 | ✗ 참고 |
| 신용카드 발급매수 | 1억 3,466만 매 (2025) 🔵 | **카드 장수** | ✗ 사람 수 아님 |
| 개인카드 국내 이용액 누계 | 약 275.97조원 🔵 (여신금융협회 월간통계, 2026.06) | 누계 거래액 | ✗ 사람 수 아님 |

**채택 근거** — 마이데이터 가입 건수만이 "지출을 능동적으로 확인하는 사람"이라는 **서비스 자격 조건과 직접 연결**된다. 마이데이터를 쓰지 않는 사람은 계산에 필요한 과거 소비 데이터를 애초에 제공할 수 없다.

### 산식

```
SAM = [ Σ(연간 소비변화 이벤트 발생 인원) − 중복 ] × 마이데이터 이용률
SOM = SAM × Beachhead 비중 × 초기 채널 도달률 × 조합안 선택률
```

**민감도 3시나리오**

| 시나리오 | 중복률 | 마이데이터 이용률 | 산출 |

## 탭 06 · Opportunity Score

### 산식

```
AOS = Importance × (1 − Satisfaction / 5)
DOS = (Importance − Satisfaction) × Market Relevance
Market Relevance = 인원 비중 × 도달가능성   (2요인 모델)
```

> ⚠️ **원본 문서가 두 개의 다른 기회점수 공식을 쓴다.** AOS 절은 `Importance × (1 − Satisfaction/5)`를, DOS 절은 `(Importance − Satisfaction) × Market Relevance`를 쓴다. 원본 DOS 표의 12개 값 전부가 후자로만 재현된다(예: C SOM = (4−1)×1.00 = 3.00. 전자로 계산하면 3.2×1.00 = 3.20이 되어 원본과 불일치).
>
> **결과적으로 AOS와 DOS는 같은 척도 위에 있지 않다.** 순위 비교(A·C 역전)는 각 표 안에서만 유효하고, AOS 값과 DOS 값을 직접 견주면 안 된다. 채점자가 검산할 수 있는 지점이므로 이 각주를 지우지 않는다. → 탭10 U-11

### 결론

**A와 C는 사실상 공동 1위다.** 모수를 SOM(낙관적 도달가능성)으로 잡으면 A(3.04 vs 3.00), SAM(보수적)으로 잡으면 C(2.40 vs 2.32)가 앞선다. **어느 쪽이든 격차가 0.1 미만이다.** **두 값이 어떤 시나리오에서도 붙어 있다는 것 자체가 이 결론을 지지한다.**

B는 양쪽 3위, F는 양쪽 4위, D·E는 5·6위로 **순위가 모수와 무관하게 안정적**이다 — 흔들리는 지점은 A·C뿐이다.

F는 AOS 단독으로는 A·C와 동급(3.2, Q1 혁신기회)이었지만 **시장 가중 후 4위로 크게 밀린다** — DOS 니치. 그래서 F는 별도 기능을 만들지 않고 **"이벤트 선택 단계를 두지 않는 것"만으로** 대응한다.

### 문제 구조 추상화 — 왜 산업을 넘을 수 있나

**낮은 수준의 정의**: "뱅크샐러드에 미래지출 입력 기능이 없다" → 기능 추가 제안에 머문다.

**구조적 정의**: 개인화 추천이 과거 행동 데이터에 의존하면, **소비구조가 크게 변하기 직전에는 추천에 필요한 데이터가 아직 존재하지 않는다.** 그래서 사용자는 중요한 결제 의사결정 시점에 미래의 자신에게 맞는 결제수단을 판단할 수 없다.

**문제의 본질은 추천 정확도가 아니라 시간축이다.**

| 구조 | 같은 구조를 갖는 문제 |
| --- | --- |
| 현재 상태와 미래 목표 상태의 차이 | 투자 포트폴리오 리밸런싱 |
| 변경 효익과 변경비용 비교 | 자산배분·설비교체·SaaS 마이그레이션 |
| 여러 제약 안에서 최적 구성 결정 | 포트폴리오 최적화·자원배분 |
| 복잡한 계산을 판단 가능한 형태로 전달 | 금융자문·보험설계·대출비교 |
| 미래 입력값이 바뀌면 다시 계산 | 시나리오 플래닝 |

### 믹스매치 6기준 점검

| 기준 | 뱅크샐러드 | 핀트 | 토스 | 스마트초이스 | TMAP TMS |

| 문제 적합성 | ✅ | ✅ | ✅ | ✅ | ❌ |
| 가치 적합성 | ✅ | ✅ | ✅ | ✅ | — |
| 맥락 적합성 | ✅ 저빈도·저리스크 조정 | ✅ 정기 주기 제거 | ✅ 톤 검증 필요 표기 | ✅ 과거→미래 축 변경 | ❌ |
| 도메인 적합성 | ✅ 근거 공개로 설명의무 | ✅ 계산·설명 분리 | ✅ 순혜택 종속 표기 | ✅ 공적 신뢰 포지셔닝 제외 | — |
| 운영 가능성 | ✅ 오류 신고만으로 충분 | ✅ 임계치 하드코딩 후 튜닝 | ✅ A/B 검증 | ✅ 규칙 엔진 재사용 | — |
| 검증 가능성 | ✅ 입력 완료율·채택률 | ✅ 트리거 대비 채택률 | ✅ 첫 화면 이탈률 | 🟠 전환율 미확보 | — |

**두 제외의 성격이 다르다.**
- **TMAP TMS**는 **첫 기준에서 탈락**했다. 문제 구조가 다르면 뒤 5개 기준은 성립하지 않으므로 적용하지 않았다. 남는 건 "다대다 최적화를 자동화한다"는 일반론뿐이고, 이건 모든 최적화 엔진의 공통점이라 **이름·은유를 가져오면 잘못된 직관을 심는다.**
- **스마트초이스**는 **6기준을 다 통과했는데도** 제외했다. 기준 통과와 "기존 채택 사례에 없던 새 메커니즘을 주는가"는 다른 문제다. 교차 산업이라는 이유만으로 남기면 **"이색 사례 수집"**이 된다.

> 서로 다른 이유로 제외된 두 사례를 남긴 것 자체가 교차 산업을 폭넓게 검토했다는 근거다.

### 믹스매치 근거 — 세 메커니즘이 각각 하나의 이탈을 막는다

| 뱅크샐러드 이탈 지점 | 막는 메커니즘 |
| --- | --- |
| **변경 판단** — "굳이 새 카드를 만들 만큼 차이가 큰가" 🟡 | 핀트식 게이팅 — "바꿀 가치가 있을 때만 알려주기" |
| **신뢰 판단** — "미래 소비가 없는데 이 혜택을 확신할 수 있나" 🟡 | 토스식 Decision UX + 근거 6항목 |
| **추천 확인** — 곧 발생할 고액지출이 반영되지 않음 ⚪ | 미래지출 입력 (F-01) |

### To-Be 핵심 흐름의 두 원칙

1. 카드 한 장을 고르는 게 아니라 **해지·유지·신규추가를 함께 계산해 하나의 조합으로 압축**한다.
2. **"유지"도 정상적인 추천 결과다** — 무조건 신규카드를 추천하지 않는다.

마지막 단계(카드사 신청 페이지 연결)는 신청서 작성·제출을 대신하지 않는다. 뱅크샐러드와 동일하게 **이동 링크만** 제공하며, **해지는 이 단계 대상이 아니다.**

### 이 탭에서 확인한 부재

**전환율·완료율류 벤치마크 수치가 이 탭에도, 저장소 어디에도 없다** — 그래서 북극성 목표 40%에 외부 앵커가 없다(→ 탭10 U-02). 없는 근거를 만들어 붙이지 않고 "팀 합의 임계치"로 성격을 표기했다.
