## SUMMARY

- **미래 지출을 사용자가 직접 입력받아 재계산하는 대규모 서비스가 이미 존재합니다** — 국세청 홈택스 연말정산 미리보기. 입력 대상이 하필 "카드 사용액"이라 도메인까지 겹칩니다. 우리 "가장 큰 가정"을 반박이 아니라 **지지**하는 선례입니다.
- **"과거 데이터 기반 추천의 한계"는 우리만의 관찰이 아닙니다** — AWS 클라우드 비용 최적화 영역에서 같은 공백이 공개적으로 지적되고 있습니다. 문제정의의 일반성이 올라갑니다.
- **보험 리모델링은 우리보다 앞서 같은 함정을 밟은 도메인입니다** — "무조건 해지·재가입 말고 점검부터"라는 업계 경고가 F-05의 해지 마찰 문제와 동일합니다.
- **경쟁 정의를 다시 그려야 합니다** — 미래 입력을 받는 서비스는 여럿 있고 결제수단을 최적화하는 서비스도 여럿 있는데, **둘을 동시에 하는 곳이 없습니다**. "카드추천 6곳 중 없음"보다 방어력이 강한 축입니다(4절).

## 1. A급 — 문제 구조가 거의 동일한 사례

### 1-1. 홈택스 연말정산 미리보기 (국세청 · 세무/공공)

| 항목 | 내용 |
| --- | --- |
| 참고 사례와 맥락 | 근로자가 11월 초~다음해 1월 말에 이용. 1~9월 실제 카드·현금 사용액과 전년 공제 내역이 미리 채워진 상태에서 시작 🔵 |
| 해결하는 문제 구조 | 남은 기간의 지출을 어떻게 쓰느냐에 따라 결과(환급액)가 달라지는데, 사용자가 그 인과를 스스로 계산할 수 없다 |
| 핵심 작동 원리 | **확정 데이터(1~9월) + 사용자가 직접 입력한 미래 예상 지출액(10~12월)을 섞어 재계산**하고, 결과를 바꿀 수 있는 조정 레버(카드 사용액·연금저축 IRP 납입·월세)를 함께 제시 🔵 |
| 효과 근거 | 국세청 공식 서비스로 매년 운영, 2025년 귀속분 개통 보도자료 존재 🔵 / 실제 이용자 수·입력 완료율은 🟠 미확인 |

> **이 사례가 왜 중요한가**: 브리프 7절의 가장 큰 가정은 *"사용자가 몇 개월 앞선 미래 소비 변화를 스스로 예측하고 입력할 의향과 능력이 있다"* 였고, 그 최대 위험 신호가 더쎈카드 종료였습니다. 그런데 국세청은 같은 입력 행위를 **카드 사용액을 대상으로** 매년 대규모로 받고 있습니다. 즉 "미래 지출 입력"이라는 행동 자체는 이미 성립하는 것으로 보이고(⚪), 더쎈카드의 실패 원인을 "입력 의향 부재"로 단정할 근거가 약해집니다 — 다른 원인(혜택 Rule 최신성 유지, 유통 채널, 수익모델)을 찾아야 합니다.
>
> **반대로 짚일 위험**: 국세청은 무료 공공 서비스이고 목적이 절세입니다. "국세청이 이미 하는데 왜 필요한가"라는 반문에는 *목적이 세금 최적화이지 결제수단 혜택 최적화가 아니다* 라는 구분으로 답해야 합니다.

### 1-2. AWS Savings Plans / Reserved Instance 추천 (B2B 클라우드 비용)

| 항목 | 내용 |
| --- | --- |
| 참고 사례와 맥락 | 기업이 클라우드 사용량에 대해 1~3년 약정(commitment)을 구매할 때, 어떤 약정을 얼마나 살지 결정 |
| 해결하는 문제 구조 | 선택지(약정 유형·기간·커버리지)가 복잡하게 얽혀 있어 최적 조합을 스스로 판단하지 못한다 — **우리 5절 구조적 정의와 동일** |
| 핵심 작동 원리 | 과거 사용량으로 추천을 생성하고, 기존 약정을 반영해 미커버 On-Demand 지출을 추정 🔵 |
| 효과 근거 | 약정 조합 최적화로 통상 30~50% 절감이 보고됨 ⚪(벤더·컨설팅 블로그 다수) |

> **핵심 인용**: Cost Explorer의 추천은 *"entirely backward-looking — 계획된 마이그레이션, 계절성, 이미 알고 있는 성장을 인식하지 못한다"* 는 한계가 공개적으로 지적됩니다(⚪, 서드파티 FinOps 벤더 블로그). 우리가 카드 도메인에서 하려는 지적과 **문장 구조가 같습니다.** 구조 대응: 약정 조합 ↔ 카드 조합, 커버리지·약정 구간 ↔ 전월실적 구간.

### 1-3. 보험 리모델링 · 내보험찾아줌 (보험)

| 항목 | 내용 |
| --- | --- |
| 참고 사례와 맥락 | 생명·손해보험협회 공동 운영 "내보험찾아줌"으로 보유 보험 전체를 조회하고, 보험사·플랫폼(토스 등)이 보장 분석·재설계를 제공 🔵 |
| 해결하는 문제 구조 | 보유 포트폴리오가 현재 상황과 맞지 않는데, 무엇을 유지·축소·해지할지 스스로 판단하지 못한다 — **F-03(보유 자산 재배치)과 동일** |
| 핵심 작동 원리 | 보유 계약 일괄 조회 → 보장범위·금액·기간·보험료 진단 → 보완안 제시 🔵 |
| 효과 근거 | 업계·언론이 반복 경고: **"무조건 해지·재가입이 아니라 보장 점검부터"** 🔵 |

> **가져올 교훈이 성공이 아니라 실패 쪽입니다.** 이 도메인은 "재설계"가 곧 "해지·재가입 유도"로 변질되는 문제를 이미 겪었고, 그래서 업계 가이드가 해지를 뒤로 미루라고 말합니다. 리서치 1-4-1의 카드 해지 마찰과 합치면, **F-05를 "해지 제안"이 아니라 "유지 vs 축소 vs 해지 3단 판단"으로 재설계하는 근거**가 됩니다.

## 2. B급 — 조건 입력 → 최적안 재계산 (메커니즘 참고용)

| 도메인 | 사례 | 작동 원리 | 우리와의 차이 |
| --- | --- | --- | --- |
| 통신 (공공) | **스마트초이스** — 방통위·KAIT 통신요금정보포털의 "사용량 기반 요금제 추천" 🔵 | 사용량을 입력받아 요금제를 산출, 결과에 "실제 요금은 이용량·할인 프로그램에 따라 달라진다"는 면책을 명시 🔵 | 입력이 **과거 사용량**이지 미래 계획이 아님 |
| 통신 (민간) | **모요(모두의요금제)** — 알뜰폰 요금제 약 1,700개 비교 🟡(플랫폼 주장) | 데이터량만 선택하면 후보를 좁혀줌 — 선택지 축소(ⓐ) 메커니즘 | 조합이 아니라 단일 상품 선택 |
| 대출 | **핀다 대출 갈아타기 계산기** + 금융위 대환대출 인프라(23개 플랫폼·53개 금융회사 참여) 🔵 | 보유 대출을 입력받아 갈아탈 때의 결과를 예측·진단 | 보유 1건 교체이지 조합 재배치가 아님. 금리 인하 폭은 🟡 업체 주장(평균 4.23%p) |
| 교통 | **기후동행카드 vs K-패스** 비교 — 월 교통비 약 77,000원이 손익분기로 통용 ⚪ | 내 이용 패턴 기준 정액권 vs 환급 중 어느 쪽이 유리한지 계산 | **주목: 이 비교 콘텐츠를 카드고릴라·핀다가 직접 만들고 있습니다** 🔵 — 경쟁사가 이미 같은 계산을 하고 있으나 계산기가 아니라 기사 형태 |
| 전력 | 한전 사이버지점·정부24 전기요금 계산기 — 선택요금제·아파트 계약방식별 비교, **이사 요금 계산** 제공 🔵 | 조건을 바꿔 넣어 요금을 미리 예측 | 주택용은 누진제라 시간대 최적화(TOU)는 사업용 중심 🔵 — 브리프의 "전력 시간대 요금 최적화" 후보는 B2C 근거가 약함 |

> 브리프 6절이 1순위로 올려둔 세 후보 중 **대환대출과 통신요금제는 근거가 확인됐고, 전력 시간대 요금 최적화는 주택용에 적용되지 않아 약합니다.** 교체 후보로 교통(정액 vs 환급)이 더 적합합니다 — 손익분기 계산 구조가 전월실적 구간과 닮았습니다.

## 4. 문제정의(07 JTBD)에 미치는 영향 3가지

**① 가장 큰 가정의 지위가 바뀝니다.** "사용자가 미래 지출을 스스로 입력할까"는 완전 미검증 가정이 아니라 **다른 도메인에서 이미 대규모로 성립 중인 행동**입니다(홈택스, 은퇴 시뮬레이터, 웨딩 예산 관리). 검증해야 할 진짜 가정은 한 단계 좁아집니다 — *"카드 혜택 최적화라는 보상 크기가 입력 노동을 정당화할 만큼 큰가"*.

**② 경쟁 정의를 2축으로 다시 그리세요.** 현재 "실행설계·미래소비반영·근거공개 3조건"은 카드추천 6곳만 놓고 만든 표입니다. 교차 도메인을 넣으면 이렇게 갈립니다:

| | 결제수단 조합을 최적화함 | 최적화하지 않음 |
| --- | --- | --- |
| **미래 지출 입력을 받음** | **(빈칸 — 우리 위치)** | 홈택스 미리보기, 은퇴 시뮬레이터, 웨딩북 예산관리, Monarch Forecasting |
| 과거·현재 데이터만 씀 | 뱅크샐러드, 카드고릴라, 토스, 카카오페이, Credit Karma, NerdWallet | 스마트초이스, 모요, 핀다 |

"카드추천 6곳 중 없음"은 표본을 좁게 잡아서 나온 결론이라는 반문이 가능한데, 이 2축은 **도메인을 넓혀도 빈칸이 유지된다**는 걸 보여줍니다.

**③ JTBD "대안" 필드의 답이 나왔습니다.** 혼인 Beachhead가 지금 이 일을 처리하는 방법은 카드추천 서비스가 아니라 **웨딩 플랫폼의 예산 관리 기능 + 결혼비용 견적**입니다. 게다가 웨딩북은 캐시백을 자기가 지급하고 있어 카드 혜택과 부분적으로 경쟁·중복합니다. 07 JTBD의 대안·장애물 서술은 여기서 출발해야 합니다.
