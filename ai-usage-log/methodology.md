## SUMMARY

- 이 폴더는 `decision-log/` 폴더와 같은 구조로 운영합니다 — `ai-usage-log.md`에 작업할 때마다 한 행씩 누적하고, **기존 행은 수정하지 않습니다.**
- 기록 기준은 6컬럼: **작업 · AI 활용 · 잘된 점 · 잘되지 않은 점 · 직접 보완 · 검증·반영 판단**
- AI는 "검색·요약·구조화·초안" 같은 확산적 작업에 적극 활용하고, "출처 신뢰성 판단·전이 적합성·법적 책임" 같은 최종 판단은 반드시 사람이 합니다.
- 존재하지 않는 수치·기능·법규를 AI가 그럴듯하게 생성해 그대로 쓰는 것이 이 로그가 막으려는 핵심 리스크입니다.

## 1. 왜 이 로그가 필요한가

평가 기준(README.md) 중 "AI 활용·협업·발표 완성도"(5점)는 **AI를 썼는지 여부가 아니라, AI 검증과 팀 의사결정이 투명한지**를 봅니다. 이 로그가 비어 있으면 그 근거가 없다는 뜻이 됩니다. 또한 방법론.md 12-3(피해야 할 패턴)의 "내부 정답 단정"·"규제 사후 첨부" 같은 실수는 대부분 AI 산출물을 검증 없이 그대로 쓴 데서 시작되므로, 이 로그를 채우는 행위 자체가 그 실수를 막는 체크포인트입니다.

## 2. AI 활용 3원칙

| 구분 | 내용 |
| --- | --- |
| ✅ 활용 권장 | 검색 질문 확장, 사례 후보 탐색, 자료 요약, 문제 추상화 후보, 비교표 구조화, 예외 케이스 발산, PRD 문장 윤문 |
| 🧑‍⚖️ 직접 판단 필수 | 출처의 실제 존재와 신뢰성, 시장·세그먼트 전제, 사례의 문제 적합성, 전이·제외 판단, 산업별 법·윤리·운영 책임, 요구사항 우선순위 |
| 🚫 금지 | 존재하지 않는 서비스 기능·사용자 반응·성과 수치·법규·API를 생성해 사실처럼 사용하는 행위 |

## 3. 로그 컬럼 가이드

| 컬럼 | 작성 기준 |
| --- | --- |
| 작업 | 무엇을 하기 위한 작업이었는지 (예: "카드 혜택 계산 로직 초안") |
| AI 활용 | 어떤 AI/도구를 어떤 용도로 썼는지 (예: "Claude로 카드사 5곳 혜택 비교표 초안 작성") |
| 잘된 점 | AI 산출물이 실제로 도움이 된 부분 |
| 잘되지 않은 점 | AI가 틀렸거나, 확인이 필요했거나, 그대로 못 쓴 부분 — **여기가 비어 있으면 검증을 안 했다는 신호**이니 반드시 채웁니다 |
| 직접 보완 | 사람이 무엇을 다시 확인·수정·추가했는지 |
| 검증·반영 판단 | 최종적으로 반영했는지, 반영 안 했는지, 조건부 반영인지 |

## 5. 운영 규칙

- **표 맨 아래에 새 행 추가** — 기존 행 수정 금지(변경이 필요하면 새 행으로 재작성 이력을 남깁니다, `decision-log.md`와 동일한 원칙)
- 작업 단위로 기록합니다. 대화 한 번 = 한 행이 아니라, **의미 있는 산출물 하나 = 한 행**입니다
- "잘되지 않은 점"이 없다고 판단되면 최소한 "특이사항 없음"이라도 적어, 검증을 건너뛰지 않았음을 표시합니다

## 6. INSIGHT

- 이 로그는 평가표의 "AI 활용·협업·발표 완성도" 항목과 최종 제출 패키지의 `03_Decision_AI_Usage_Log`를 동시에 충족시키는 문서입니다 — 발표 직전에 급조하지 말고 매 작업 직후 바로 기록하는 습관이 완성도를 좌우합니다.
- `decision-log/decision-log.md`와 이 로그를 같은 방식(표 맨 아래 추가, 기존 행 보존)으로 운영하면, 두 로그를 나란히 보면서 "어떤 결정이 AI 제안에서 시작됐는지" 역추적할 수 있어 최종 발표의 "AI 검증 투명성" 근거로 그대로 쓸 수 있습니다.
