## 0. 최종 판단

**세 가지가 이 방법론의 결론이다.**

1. **Job은 페르소나 단위가 아니라 Job 단위로 선언해야 한다.** 이전 버전은 페르소나 12명 단위로 선언을 나열했으나 이는 JTBD 원칙과 어긋난다 — 같은 Job을 여러 페르소나가 공유하는데 페르소나 수만큼 선언을 늘리면 **사실상 같은 선언이 반복**된다. 그래서 **Job(=AOS 후보 A~F) 단위로 재구성**했다.
2. **가장 큰 가정이 두 번 좁혀졌다.** 검증할 것은 더 이상 *"사용자가 미래 지출을 입력할까"*가 아니라 **"카드 혜택 최적화라는 보상이 입력 노동을 정당화할 만큼 큰가"**다. 이는 [03](03_KSF.md) KSF③이 [01](01_Five_Forces.md)의 대체재("아무것도 안 하기")를 이길 만큼 강력한지에 대한 검증과 **같은 질문**이다.
3. **모의 인터뷰 응답이 정량 분석과 일치했다** — A·C에 가장 강한 긍정 반응, F는 *"인정받는 느낌은 들었지만 완전한 확신은 없었다"*(오세훈)로 DOS 니치 판정과 정확히 일치, 조민아의 *"입력 수고 대비 가치 부족"*으로 최대 리스크가 **해소되지 않았음**이 확인됐다.

> ⚠️ **3번이 이 방법론의 최대 한계이기도 하다.** 응답이 정량 분석과 일치한 것은 **같은 팀이 같은 전제로 작성했기 때문일 수 있다.** 모의 응답은 가설을 반박하는 힘이 약하다 — 그래서 E1(실제 인터뷰 n=15)이 필요하다.

### 1-5. 질문지 구조 — 4가지 전환 동인 태깅

| 절 | 포착 대상 | 대표 질문 |
| --- | --- | --- |
| 4-1 | **Push / Pull** (대안·맥락) | *"카드 조합을 다시 짜기 전에 다른 어떤 방법을 고려하셨습니까?"* / *"그 방법이 '과거 소비 기준'이라는 걸 알고 계셨습니까, 그때 어떤 생각이 드셨습니까?"* |
| 4-2 | **Anxieties** (불안) | *"마이데이터 연동에 동의하는 것에 불안감이 있으셨습니까?"* / *"입력하는 시간·수고에 비해 얻는 게 크다고 느끼셨습니까?"* |
| 4-3 | **Habits** (발목 잡는 기존 행동) | *"지금까지 카드 실적·혜택을 어떻게 관리해 오셨습니까?"* / *"안 쓰는 카드나 자동이체를 그대로 방치해 두신 적이 있습니까?"* |
| 4-4 | 연상 유도 | *"그때는 하루 중 몇 시였습니까? 집이었습니까, 직장이었습니까?"* |

**인터뷰 상황 설정** — 참가자가 먼저 **고객용 데모 페이지를 직접 체험**한다(마이데이터 연동 시뮬레이션 → 미래 지출 입력 → 제약조건 → 시나리오 계산 → 조합 추천 → 근거 확인). 그 직후 체험 결과를 토대로 기존 경험(엑셀·카드고릴라·지인 추천·자동대체 등)과 비교해 응답한다. 순수 회상(recall)이 아니라 **실사용 체험 + 회고** 구조이므로, 문항은 *"만약 ~라면"*이 아니라 **"방금 데모에서 ~했을 때"**로 묻는다.

> **질문 설계에서 6건을 수정한 이력이 있다** — *"데모가 다수의 카드를 한 번에 스캔해 우선순위를 매겨주는 방식이었습니까?"*처럼 **우리가 이미 아는 데모 기능의 존재 여부를 인터뷰이에게 확인받는 질문**이 6건 발견돼(김도윤·한지민·오세훈·강민재·신은서·윤태호) 전부 *"~하시면서 ~라는 느낌을 받으셨습니까"*(주관적 체감)로 재작성했다. **데모 설계 주체가 우리라 기능 존재는 인터뷰 없이도 알고 있고, 새로운 정보는 그 기능을 쓴 사람의 느낌뿐**이기 때문이다(`decision-log` 2026-08-19 11:28).

### 1-7. 페르소나별 JTBD 요약 카드 — 11필드 형식

각 인물 카드는 `Persona/Segment · Situation · Job Statement · Desired Outcome · 4 Forces · Current Solutions · Switch Triggers/Barriers · Evidence · Priority(AOS/DOS) · Notes` 형식으로 12명 전원 작성됐다. 아래는 결론에 직접 인용된 4명이다.

| 인물 | Job Statement | 4 Forces 핵심 | Barrier | Priority |
| --- | --- | --- | --- | --- |
| **이서연** (Core) | 미래 지출을 카드 혜택과 미리 연결해 계산받고 싶다 | Push 정보 과부하 · Pull "미래 기준" 계산 · Habit 카페 후기 검색 유지 · Anxiety 마이데이터 동의 망설임 | 해지 시 상담사 만류 우려 | A: AOS 4.0 / DOS 3.04·2.32 |
| **신은서** (Extreme) | 계산 결과뿐 아니라 실행(해지) 자체를 끝까지 완수하고 싶다 | Push 무력감 · Pull 계산 근거의 명확성 · Habit 자동이체만 방치 · Anxiety 또 만류당할 걱정 | **상담사 만류 화법 — 카드사 통제 영역, 서비스가 개입할 수 없는 외부 요인** | C(대리): AOS 3.2 / DOS 3.00·2.40 |
| **오세훈** (Adjacent) | 이벤트명과 무관하게 소비 변화를 입력해 재설계받고 싶다 | Pull 이벤트 선택 단계가 없다는 점 | *"인정받는 느낌은 들었지만 완전한 확신은 없었다"* | F: AOS 3.2 / DOS 1.50·0.90 |
| **조민아** (Non-user) | 미래를 예측하기보다 그때그때 대응하는 것으로 충분하다고 느낌 | Push 없음 · Pull 없음 · Habit 지인 추천 카드 1장 · Anxiety **"이걸 어떻게 미리 아냐"는 근본적 불신** | **입력 수고 대비 가치 체감 부족 — "가장 큰 가정"(E-05) 붕괴** | 해당 없음(채점 제외) |

## 2. 산식·계산 — 가장 큰 가정의 두 번의 축소

정량 산식은 없다. 이 방법론의 "계산"은 **검증 대상을 좁혀 온 과정**이다.

| 단계 | 검증 대상 | 왜 바뀌었나 |
| :---: | --- | --- |
| 최초 | *"사용자가 미래 지출을 입력할까"* | — |
| **1차 축소** | 입력 자체는 **타 도메인에서 이미 대규모로 성립 중**(홈택스 연말정산 미리보기 등) | 입력 행위의 성립 여부는 더 이상 쟁점이 아니다 |
| **2차 축소(현행)** | **"카드 혜택 최적화라는 보상이 입력 노동을 정당화할 만큼 큰가"** | 이것이 **E2 Concierge Test**의 검증 대상 |

> ⚠️ **1차 축소의 근거가 비어 있다.** `가람/확정본/07` 21행이 *"타 도메인에서 이미 대규모로 성립 중"*이라 쓰지만 **확정본 어디에도 홈택스 이용자 수·입력 완료율 수치가 없다**. 확보되면 가장 큰 가정을 🟠 → 🔵로 승격할 수 있으나, **미확보 상태에서 "대규모"로 단정하지 않는다** → [10](10_Evidence_Inference_Assumption.md) U-16.

**인터뷰 표본 설계 근거** — 그룹 A 6~8 / B 2~3 / C 2~3, 총 12명 내외. 소요 시간 **60~90분**으로 잡은 이유는 **Switch Interview 형식에 익숙하지 않은 참가자가 편안해지는 데 시간이 걸리기 때문**이다. 실제 실험 표본 설계(E1 n=15)는 [09](09_PRD_Requirement_Trace.md) 8절과 `효진/0820/final/05_실험_설계서.md`에서 중단선 역산으로 재계산됐다.

## 5. 사례 비교

### 5-1. 기존 대안과의 비교 — 인터뷰가 포착한 Pull

| 인물 | 기존 대안 | 데모 체험 후 반응(모의) | 무엇이 Pull인가 |
| --- | --- | --- | --- |
| 이서연 | 뱅크샐러드(과거 기준) + 카페 후기 | *"여기는 앞으로 쓸 돈을 물어보니까"* | **시간축**(과거 → 미래) |
| 김도윤 | 개인 엑셀 가계부 | *"결혼이랑 이사 지출을 합쳐서 하나의 조합으로 딱 정리해준 게 제일 좋았어요"* | **통합·조합 단위** |
| 박서준 | 카드사 콜센터(설명 상충) | *"여기는 화면에 근거가 딱 나와 있으니까 훨씬 나았어요"* | **근거 공개** |
| 오세훈 | 카드 방치 + 지인 추천 | *"이벤트를 고르라고 해서 저는 늘 해당이 안 됐는데"* | **이벤트 선택 단계 없음** |
| 강민재 | 카드사 안내 문자 | *"카드사 문자는 그냥 안내였는데 여기는 '정리해도 된다'고 짚어줘서"* / *"근데 화면이 좀 복잡하게 느껴졌어요"* | 지출 **감소** 방향 지원 / 단 용어 난이도가 Barrier |
| 신은서 | 해지 시도 후 포기 | *"만류당할 걸 대비하는 내용까지는 없어서 여전히 막막했어요"* | **Pull이 실행 단계에서 끊긴다** |
| 윤태호 | 카드 서랍 방치 | *"우선순위는 명확하게 나왔는데, 20장이 넘으니까 화면 자체가 부담스럽게"* | Pull은 있으나 **규모가 Barrier** |
| 조민아 | 지인 추천 카드 1장 | *"몇 달 뒤를 어떻게 미리 아냐는 생각이 입력하는 내내 있었어요"* | **Pull 자체가 형성되지 않음** |
| 배정호 | 종이 가계부·창구 | *"마이데이터 연동 화면부터 이해가 안 됐고, 미래 지출 입력 화면에서 제일 막막했어요"* | Pull 없음 — 진입 자체가 막힘 |
