## 2. 윤정이 제기한 두 가지 반박

### 반박 1 — 신용카드 사용자 전체는 실사용자와 괴리가 너무 큼

> 신용카드 사용자들이 모두 이 카드 조합 추천 서비스를 이용할 거라고 생각하지 않는다. 미래 지출을 바탕으로 카드 조합을 설계하고 조언을 받으려는 사용자는, 이미 마이데이터를 사용해서 본인의 지출을 확인하는 사람일 가능성이 높다.

→ 요지: TAM=신용카드 실사용자는 **자격은 있지만 채택 가능성은 낮은 사람**을 너무 많이 포함해, 시장 규모가 실제 타겟과 동떨어져 보인다는 우려.

### 반박 2 — "신용카드 사용자"라는 정의 자체가 디지털 비친화 인구까지 포함

> 신용카드를 사용하지 않는 성인은 거의 없다. TAM을 신용카드 사용자로 잡으면 전통 금융권을 통해 카드를 발급받는, 아직 디지털에 친숙하지 않은 중장년·노년층까지 포함되는데 — 그게 적합한 정의인가?

→ 요지: "성인 대부분 = 신용카드 사용자"이므로 이 정의는 사실상 필터링 기능이 거의 없고, 우리 서비스가 실제로 서비스할 수 없는(디지털 채널 자체를 안 쓰는) 인구까지 섞여 들어간다는 우려.

## 3. 검토한 대안

### 옵션 A — TAM 자체를 마이데이터 이용자로 되돌린다

| | 내용 |
| --- | --- |
| 장점 | 반박 1·2를 TAM 단계에서 바로 해소 — 마이데이터 이용자는 지출을 능동적으로 확인하려는 의향(반박1)과 디지털 앱 사용 능숙도(반박2)를 동시에 만족 |
| 단점 | 효진이 지적한 문제가 그대로 재발함 — MVP는 마이데이터 미연동(직접입력)으로 작동하는데 TAM을 마이데이터 가입자로 제한하면, "마이데이터 없이도 쓸 수 있는 사람"을 자격 단계에서부터 배제하는 논리적 모순이 생김. 마이데이터 가입건수(1.77억 건) 자체도 중복포함·집계기준 불일치 문제가 있어 숫자가 불안정함 |

### 옵션 B(제안) — TAM은 신용카드 실사용자로 유지하고, SAM에 마이데이터 이용자 필터를 추가한다

| | 내용 |
| --- | --- |
| 핵심 아이디어 | 반박 1과 반박 2가 가리키는 해법이 사실 같다 — 마이데이터 앱(뱅크샐러드·토스·카카오페이 등)은 **①지출을 능동적으로 확인하려는 의향**이 있고 **②스마트폰 앱에 익숙한** 사람만 가입한다. 이 한 가지 조건이 두 반박을 동시에 걸러줌 |
| 구조 | TAM(신용카드 실사용자, 자격 기준·유지) → **SAM = TAM × 마이데이터 이용자 비율(디지털 친화·지출추적 성향 프록시) × 소비구조 변화 이벤트 발생 비율(혼인·이사 등, 효진 절차서 Phase 1)** |
| 장점 | TAM은 "이 문제를 가질 자격이 있는 사람"이라는 정의를 유지해 심사자에게 방어 가능(효진 지적과 충돌 없음). SAM 단계에서 실제 서비스·채택 가능 인구로 현실적으로 좁혀져 반박 1·2가 모두 해소됨 |
| 단점/과제 | 마이데이터 이용자 비율의 실수치가 필요 — 효진의 `TAM-SAM-SOM 정의 작업안.md` 절차(KOSIS 등 원자료 수집)와 연계해서 채워야 함 |
