### 1-4. 📶 스마트초이스 — 통신 요금제 진단 (교차 산업, 채택)

| 항목 | 내용 |
| --- | --- |
| 참고 사례와 원래 맥락 | 한국통신사업자연합회(KTOA)·통신 3사·정부가 공동 운영하는 통신요금 정보포털. 최근 3개월 평균 사용량(데이터·음성·문자)을 기준으로 통신 3사 요금제 중 최적안을 추천하며, Open API로도 제공되어 월평균 사용량·연령·통신망 구분·약정정보를 입력하면 최저 요금제를 반환한다(🔵 [스마트초이스](https://www.smartchoice.or.kr/smc/plan/recomend_search03_2_3.do?type=m)) |
| 해결하는 문제 구조 | 비교 복잡성 — 요금제 구조(데이터·음성·문자 단가, 결합할인, 약정조건)가 복잡해 사용자가 스스로 최적안을 계산하지 못함. "사용 패턴을 규칙에 대입해 상품을 재매칭"한다는 점에서 카드 조합 문제와 문제 구조가 같다 |
| 핵심 작동 원리 | 실사용 데이터를 요금제 규칙에 대입해 계산 엔진이 자동으로 최적 상품을 도출 — 정부·산업 공동 운영이라는 공적 신뢰 장치를 결합 |
| 효과 근거 | 공개 지표(정부·통신3사 공동 운영, 공식 Open API 존재, 🔵) · 사용자 반응·전환율 지표는 미확인(🟠) |
| 그대로 유지할 요소 | "사용 패턴 → 규칙 엔진 대입 → 최적 상품 계산"이라는 구조 자체 — 이 구조가 통신 시장에서 이미 공인된 방식이라는 사실이 카드 조합 계산 방식의 타당성을 뒷받침한다 |
| 변형할 요소 | 스마트초이스는 현재 사용 패턴만 보고 계산하지만(과거 지향), 이 서비스는 미래 변화값을 추가로 반영해야 한다. 스마트초이스는 요금제 1개만 추천하지만, 이 서비스는 카드 여러 장의 조합을 동시에 최적화해야 한다 |
| 제외할 요소 | "공적 기관이 운영하는 공인 계산기"라는 신뢰 포지셔닝 — 민간 서비스인 이 서비스는 공적 권위 대신 계산 근거를 직접 투명하게 공개하는 방식으로 신뢰를 만들어야 한다 |
| 개선안 반영 | 계산 엔진 전체 구조(사용 패턴/지출 → 규칙 대입 → 최적 조합)가 이미 인접하지 않은 산업(통신)에서 공인된 접근이라는 근거로 활용 |

### 1-5. 🚚 TMAP TMS (교차 산업, 제외)

| 항목 | 내용 |
| --- | --- |
| 참고 사례와 원래 맥락 | TMAP 모빌리티의 배차·경로 최적화 API — 다중 경유지·차량을 대상으로 배송거리·화물량·배송시간을 동시에 고려해 배차·경로·도착예정시간을 산출(🔵 공식 API 설명) |
| 해결하는 문제 구조 | 다대다 제약 최적화 — 여러 개체(차량)를 여러 목적지(배송지)에 제약조건 하에서 동시에 배분 |
| 핵심 작동 원리 | 인지부하 위임 — 시스템이 조합을 대신 계산해 복잡성을 숨기고 결과만 제시 |
| 효과 근거 | 공식 API 설명(🔵) |
| 그대로 유지할 요소 | 없음 |
| 변형할 요소 | 해당 없음 |
| 제외할 요소 | 배차·경로·재배차라는 은유 전체. TMAP은 이동거리·시간창이라는 연속 비용과 방문 순서(시퀀싱)가 핵심 구조인데, 카드 조합 문제는 지출 건 사이에 이동거리·순서 개념이 없는 실적구간 채우기 문제라 원본-대상 구조가 다르다. 남는 건 "다대다 최적화를 자동화한다"는 가장 일반적인 사실뿐이며, 이는 TMAP 고유 특징이 아니라 모든 최적화 엔진의 일반론이라 이름과 은유를 가져오면 잘못된 직관을 심을 위험이 있다 |
| 개선안 반영 | 다중카드 배분 계산(Rebalancing Optimization Engine)은 TMAP의 은유·이름과 무관하게 독립적으로 설계한다 |

## 2. 믹스매치 의사결정 기준 점검

| 기준 | 뱅크샐러드 | 핀트 | 토스 | 스마트초이스 | TMAP TMS |
| --- | --- | --- | --- | --- | --- |
| 문제 적합성(같은 문제 구조인가) | ✅ 손실 인식 부재 | ✅ 개입 시점 불확실성 | ✅ 정보 과부하 | ✅ 비교 복잡성(구조 동일) | ❌ 연속 비용·시퀀싱 구조가 달라 불일치 |
| 가치 적합성(중요한 행동·결과 개선) | ✅ 전환 동기 형성 | ✅ 불필요한 전환 방지 | ✅ 실행률 향상 | ✅ 계산 방식의 타당성 근거 | — |
| 맥락 적합성(빈도·긴급성·리스크·책임 차이 반영) | ✅ 카드는 투자보다 저빈도·저리스크로 조정 | ✅ 정기 주기 제거로 반영 | ✅ 금융 의사결정 신중함 고려해 톤 검증 필요로 표기 | ✅ 과거→미래 축 변경으로 반영 | ❌ 반영해도 구조 자체가 안 맞음 |
| 도메인 적합성(설명의무 등 책임과 충돌 여부) | ✅ 근거 공개로 설명의무 충족 | ✅ 계산과 설명 분리(G-04)로 충돌 없음 | ✅ 순혜택 종속 표기로 이탈유인 방지 | ✅ 공적 신뢰 포지셔닝은 제외해 충돌 없음 | — |
| 운영 가능성(CS·심사·정산·예외 대응) | ✅ 계산 오류 신고만으로 충분 | ✅ 임계치 하드코딩 후 튜닝 | ✅ A/B 테스트로 검증 가능 | ✅ 규칙 엔진 구조 재사용 가능 | — |
| 검증 가능성(성공·실패 판단 지표) | ✅ 시나리오 입력 완료율·채택률 | ✅ 트리거 발생률 대비 채택률 | ✅ 첫 화면 이탈률·근거 진입률 | 🟠 전환율 지표 미확보 | — |

TMAP TMS는 첫 기준(문제 적합성)에서부터 불일치가 확인되어, 나머지 5개 기준을 적용할 실익이 없다고 판단했다 — 문제 구조가 다르면 그 뒤의 가치·맥락·도메인·운영·검증 적합성은 애초에 성립하지 않는다.

## 3. 종합

| 사례 | 산업 관점 | 판단 | 개선안에 반영되는 것 |
| --- | --- | --- | --- |
| 뱅크샐러드 | 동일 금융 | ✅ 채택(변형) | 손실 프레이밍(과거→미래 축 전환) |
| 핀트 | 인접 금융 | ✅ 채택(변형) | Net Benefit 게이팅(정기 주기 제거) |
| 토스 | 동일 금융(UX) | ✅ 채택(변형) | 결론 우선 UX(장단점 병렬 제시 방식만 변형) |
| 스마트초이스 | 교차 산업(통신) | ✅ 채택(변형) | 계산 엔진 구조의 타당성 근거 |
| TMAP TMS | 교차 산업(물류) | 🔶 제외 | 은유·이름 전체 미채택 — 독립 설계 근거 |

3개 사례에 그쳤던 관점을 5개로 넓히면서, 동일·인접·교차 산업이 모두 포함됐고 교차 산업에서 채택과 제외 사례를 하나씩 확보했다. TMAP TMS를 제외 사례로 남겨둔 이유는 "구조가 다른 사례를 걸러내는 판단 기준"(문제 적합성)을 보여주기 위함이며, 스마트초이스를 채택 사례로 추가한 이유는 "사용 패턴 기반 상품 재매칭"이라는 이 서비스의 핵심 구조가 카드 시장에서만 통하는 특이한 발상이 아니라 통신 시장에서도 이미 검증된 접근이라는 근거가 되기 때문이다.
