05 · User Stories & AC

사용자 스토리와 수용 기준

우선순위는 JTBD Job 선언(A·C 공동 1위, B 3위, F 니치)을 그대로 따릅니다. 각 스토리의 수용 기준(AC)은 아래에서 펼쳐 확인하세요.

AC1 · 성능

마이데이터 연동을 완료한 사용자가 미래 지출 카테고리·금액·시점을 입력하면, p95 ≤ 5,000ms 안에 시나리오 계산 결과가 표시된다.

AC2 · 차액 표시

결과 화면에서 현재 조합 유지 시 예상 혜택과 추천 조합 예상 혜택의 차액이 원 단위로 표시된다 (계산 오차 ≤ 100원 — 규칙 기반 결정론적 계산이므로 사실상 0 허용).

AC3 · 이탈률

신규 사용자가 온보딩을 진행하면, 미래 지출 입력 완료까지의 주간 이탈률이 30% 이하로 유지된다.

⚠️ 이 스토리에 대응하는 기능은 측정(Execution Completion Rate)뿐입니다. 해지 상담·신청 대행·만류 대응 안내 등 실행 지원 기능은 어떤 형태로도 설계하지 않습니다 (마이데이터 기반 서비스는 직권·대행 권한이 없음).

AC1 · 집계

추천 조합 확인 후 30일이 경과하면, 앱 내 자기신고(“완료했어요” 버튼) 또는 재방문 행동으로 실행 여부를 Execution Completion Rate에 집계한다.

AC2 · 격차 경보

분기 종료 시 Payment Plan Selection Rate와 나란히 리포트해 “선택했지만 미실행” 격차를 정량화한다 (격차 20%p 이상이면 경보 🟡).

AC3 · 후속 액션 없음

미완료 자기신고 사유(상담사 만류/시간 부족/기타)는 지표 집계에만 사용하고, v0.1에서는 어떤 후속 액션 기능도 자동 트리거하지 않는다.

AC1 · 근거 펼침

“근거 보기”를 클릭하면 적용된 실적구간·혜택한도·연회비 규칙이 항목별로 p95 ≤ 1,000ms 안에 펼쳐진다.

AC2 · 제외 비용 명시

계산에 포함되지 않은 비용(포인트 소멸·자동납부 승계 등)이 있을 때 “이 계산에는 포함되지 않았습니다” 문구가 누락 없이(누락률 0%) 표시된다.

AC3 · 열람율

근거 화면 노출 후 주간 집계 시 근거 화면 열람율이 50% 이상이다 🟡.

AC1 · 필수 이벤트 0개

온보딩에서 지출 변화를 입력할 때 이벤트 종류를 선택하는 필수 단계는 0개다.

AC2 · 양방향 처리

지출 변화가 감소 방향일 때도 시스템은 증가·감소 방향 모두를 오류 없이(처리 오류율 0%) 처리한다.

AC3 · 인정 만족도

F 해당 사용자가 결과를 받으면 “내 상황이 인정받았다” 만족도(5점) 평균 3.5점 이상을 목표로 한다 🟡.

06 · Features

기능 요구사항 (MoSCoW)

각 기능은 대안 대비 가치로 정당화됩니다. 계산 엔진은 결정론적 규칙 기반이며, AI는 근거 설명(자연어)에만 씁니다.

Must

  • F-01미래 지출 변화 입력(카테고리·금액·시점, 이벤트 선택 강제 없음) — 경쟁 6곳 중 미래소비반영 0곳 🔵, 유일한 차별점
  • F-02마이데이터 연동(과거 소비·보유카드 자동 수집) + 제약조건 입력 — 입력 부담 완화
  • F-03시나리오 계산(실적구간·한도·연회비 반영 순혜택 산출) — 뱅크샐러드도 아직 과거 1년 기준
  • F-04보유·신규카드 조합 비교, 최종 1안 제시 — 경쟁자 전원 단일 카드 비교에 그침
  • F-06계산 근거 공개(적용 규칙·제외 조건 포함) — 민원 +88.4% 불신에 직접 대응
  • 측정Execution Completion Rate(자기신고 + 재방문 감지, 대행 아님) — KPI 사각지대 해소

Should

  • 초기값온보딩 초기값 자동 제안(과거 패턴 기반) — “가장 큰 가정” 리스크 완화
  • F-05계산 근거 공개 강화(포인트 소멸·자동납부 승계 등 부수 비용 명시)

Could

  • 카드 10장 이상 보유자 대상 단계적 결과 제시(“이번 주 상위 3개”) — 정보 과부하 완화, 아직 미반영

Won’t — v0.1 Out of Scope

· 해지·전환 실행 대행/상담/안내 (직권·대행 권한 없음)

08 · Risks & Assumptions

리스크와 가정

최대 리스크 🟡

“가장 큰 가정” 붕괴

미래 지출 입력의 수고가 혜택 최적화 보상을 정당화하지 못하면 온보딩 자체가 무너진다(조민아 응답, E-05). Concierge Test에서 최우선 검증.

🔵 인가

마이데이터 인가·제휴 지속성

사업자 다수가 최근 허가를 반납. 직접 인가 취득 또는 제휴 계약의 법적 안정성이 전제조건.

정확도

카드 혜택 Rule 파편화

통합 공식 API가 없어 수작업 수집·버전관리 실패 시 계산 신뢰도 붕괴.

지표 착시

North Star 지표 착시

Payment Plan Selection Rate만 보면 신은서 같은 “선택 후 실행 실패”가 성공으로 집계됨 — Execution Completion Rate를 반드시 나란히 리포트해야 함.

가정·의존성 · 마이데이터 연동이 MVP 전제(2026-08-19 팀 결정) · Net Benefit 게이팅 로직은 11_Benchmark_Transfer 설계에 의존 · Importance·Satisfaction 점수는 현재 팀 추정(🟡)이며 Concierge Test 실측 전까지 우선순위는 잠정적.
