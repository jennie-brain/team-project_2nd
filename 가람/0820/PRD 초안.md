## 3. 사용자 스토리와 수용 기준(AC)

우선순위는 `가람/확정본/07_JTBD.md` 0절 Job 선언의 AOS·DOS 순위(A·C 공동 1위, B 3위, F 니치)를 그대로 따릅니다. D·E는 3-5절에 Should/Won't로만 축약합니다.

### Story A — 미래지출 자동 연결 (Must)

> As a 소비 구조가 곧 바뀔 예정인 카드 이용자(이서연), I want 미래 지출 변화를 카드 혜택과 자동으로 연결해 계산받고 싶다, so that 놓치는 혜택 없이 최대 혜택을 받을 수 있다.

- **AC1**: Given 마이데이터 연동을 완료한 사용자가, When 미래 지출 카테고리·금액·시점을 입력하면, Then p95 ≤ 5,000ms 안에 시나리오 계산 결과가 표시된다.
- **AC2**: Given 계산이 완료된 후, When 결과 화면을 확인하면, Then 현재 조합 유지 시 예상 혜택과 추천 조합 예상 혜택의 차액이 원 단위로 표시된다(계산 오차 ≤ 100원 — 규칙 기반 결정론적 계산이므로 사실상 0 허용).
- **AC3**: Given 신규 사용자가 랜딩한 후, When 온보딩을 진행하면, Then 미래 지출 입력 완료까지의 주간 이탈률이 30% 이하로 유지된다.

### Story C — 실행 완주 측정 (Must, 단 "측정"에 한정)

> As a 계산 결과가 해지가 유리하다고 나온 사용자(신은서·박서준), I want 계산 근거를 믿고 실제로 해지·전환까지 완료하고 싶다, so that 계산한 혜택을 실제로 받을 수 있다.

> ⚠️ 이 스토리에 대응하는 기능은 **측정(Execution Completion Rate)뿐**입니다. 해지 상담·신청 대행·만류 대응 안내 등 실행 지원 기능은 어떤 형태로도 설계하지 않습니다(마이데이터 기반 서비스는 직권·대행 권한이 없음, `윤정/확정본/02_Value_Chain.md` 5절).

- **AC1**: Given 사용자가 추천 조합을 확인한 후, When 30일이 경과하면, Then 앱 내 자기신고("완료했어요" 버튼) 또는 재방문 행동으로 실행 여부를 Execution Completion Rate에 집계한다.
- **AC2**: Given Execution Completion Rate 측정이 누적된 후, When 분기가 종료되면, Then Payment Plan Selection Rate와 나란히 리포트해 "선택했지만 미실행" 격차를 정량화한다(격차 20%p 이상이면 경보, 🟡 임계치).
- **AC3**: Given 사용자가 미완료를 자기신고할 때, When 사유를 선택하면(상담사 만류/시간 부족/기타), Then 이 데이터는 지표 집계에만 사용하고, v0.1에서는 어떤 후속 액션 기능도 자동 트리거하지 않는다.

### Story B — 신뢰 가능한 계산 근거 (Must)

> As a 계산 결과를 스스로 검증하고 싶은 사용자(최유리), I want 계산 근거를 투명하게 확인하고 싶다, so that 카드사 설명이 아니라 내가 검증한 숫자로 결정할 수 있다.

- **AC1**: Given 계산 결과 화면에서, When "근거 보기"를 클릭하면, Then 적용된 실적구간·혜택한도·연회비 규칙이 항목별로 p95 ≤ 1,000ms 안에 펼쳐진다.
- **AC2**: Given 계산에 포함되지 않은 비용(포인트 소멸·자동납부 승계 등)이 있을 때, When 근거 화면을 열람하면, Then "이 계산에는 포함되지 않았습니다"라는 문구가 누락 없이(누락률 0%) 표시된다.
- **AC3**: Given 근거 화면이 노출된 후, When 사용자 행동을 주간 집계하면, Then 근거 화면 열람율이 50% 이상이다(🟡 목표).

### Story F — 이벤트 비종속 인정 (Should — 니치, 낮은 인원 비용으로 반영)

> As a 정해진 이벤트(혼인·이사)에 해당하지 않는 사용자(오세훈), I want 이벤트명을 선택하지 않고도 소비 변화를 입력하고 싶다, so that 내 상황도 서비스 대상으로 인정받을 수 있다.

- **AC1**: Given 온보딩 화면에서, When 지출 변화를 입력하면, Then 이벤트 종류를 선택하는 필수 단계는 0개다.
- **AC2**: Given 지출 변화가 감소 방향일 때, When 입력하면, Then 시스템은 증가·감소 방향 모두를 오류 없이 처리한다(처리 오류율 0%).
- **AC3**: Given F 해당 사용자가 입력을 완료했을 때, When 결과를 받으면, Then "내 상황이 인정받았다"는 만족도(5점 척도) 평균 3.5점 이상을 목표로 한다(🟡, Concierge Test에서 실측).

## 5. 비기능 요구사항 (NFR)

- **성능**: 시나리오 계산(F-03) p95 응답 ≤ 3,000ms · 근거 화면(F-06) p95 ≤ 1,000ms
- **신뢰성**: 월 가용성 ≥ 99.5% · 계산 오류율 ≤ 0.5%(경계값 테스트: 전월실적 1원 부족, 월 한도 초과, 실적 충돌 케이스 필수)
- **보안/비용**: 마이데이터 표준 API 인가 요건 준수(자본금·물적설비·보안 요건), 카드 혜택 Rule은 적용 시작일·종료일 버전 관리 필수(`윤정/확정본/02_Value_Chain.md`)
- **모니터링 항목**: 온보딩 funnel(F-01→F-02 이탈률), 계산 오류율, 불필요한 신규카드 추천 비율, Payment Plan Selection Rate, Execution Completion Rate, 근거 화면 열람율 — 대시보드·주간 알림으로 추적

| ExecutionCompletionLog | user_id, 추천 시각, 자기신고 여부, 미완료 사유(선택), 재방문 감지 시각 |

### API 개요

| 인터페이스 | 방향 | 제약 |
| --- | --- | --- |
| 마이데이터 표준 API(카드 업권 정보제공) | 입력(외부) | 오픈뱅킹 미지원, 마이데이터 API가 유일한 경로(🔵) — API 장애 시 "최근 확인된 데이터 기준" 경고로 완화 |

## 7. 범위(In/Out), 리스크·가정·의존성

### In-Scope

F-01·F-02·F-03·F-04·F-06, Execution Completion Rate 측정, 온보딩 초기값 자동 제안(Should)

### Out-of-Scope

- 해지·전환 실행 대행/상담/안내 — 마이데이터 기반 서비스는 직권·대행 권한 없음
- 신규카드 자동 발급, 자동결제, 대출·BNPL
- 리텐션(Job E) 전용 기능, 다중카드 조합 최적화 엔진 고도화

### 리스크 (최소 3개)

1. **"가장 큰 가정" 붕괴**: 미래 지출 입력의 수고가 혜택 최적화 보상을 정당화하지 못하면 온보딩 자체가 무너짐(조민아 응답, E-05 🟡) — Concierge Test에서 최우선 검증
2. **마이데이터 인가·제휴 지속성 리스크**: 마이데이터 사업자 다수가 최근 허가를 반납(🔵) — 직접 인가 취득 또는 제휴 계약의 법적 안정성 확보가 전제조건
3. **카드 혜택 Rule 파편화로 인한 계산 정확도 리스크**: 통합 공식 API가 없어 수작업 수집·버전관리 실패 시 계산 신뢰도 붕괴
4. **North Star 지표 착시 리스크**: Payment Plan Selection Rate만 보면 신은서 같은 "선택 후 실행 실패" 사례가 성공으로 집계됨 — Execution Completion Rate를 반드시 나란히 리포트해야 함(VP Sheet 미해결 항목 #2)

### 가정·의존성

- 마이데이터 연동이 MVP 전제(2026-08-19 팀 결정)
- Net Benefit 게이팅 로직은 `윤정/확정본/11_Benchmark_Transfer.md`의 설계에 의존
- Importance·Satisfaction 점수는 현재 팀 추정(🟡)이며 Concierge Test 실측 전까지 PRD의 우선순위는 잠정적

## 8. 실험·롤아웃·측정

### 1차: Concierge Test (피치덱 9장)

- **채널**: 혼인 Beachhead(웨딩업체 제휴)
- **방식**: 사람이 직접 수동으로 응대하며 실제 수요를 미리 확인
- **가설**: "미래 지출 입력 → 계산 근거 공개" 조합이 Payment Plan Selection Rate ≥ 40%를 달성한다
- **측정**: Payment Plan Selection Rate, 온보딩 이탈률, 근거 화면 열람율

### 2차: A/B 테스트

- **가설**: 온보딩 초기값 자동 제안(과거 패턴 기반)이 있으면 없을 때보다 온보딩 완료율이 유의하게 높다
- **측정**: 온보딩 완료율(대조군 vs 실험군), 표본 크기 목표 n≥300(그룹당)
