## 1. 고객 여정 맵을 만드는 8단계

| # | 단계 | 핵심 활동 | 이 프로젝트에서의 적용 |
| --- | --- | --- | --- |
| 1 | 명확한 목표 설정 | 개선하고 싶은 프로세스와 KPI를 먼저 못 박음 | KPI = Payment Plan Selection Rate(피치덱 8장). 개선 대상 후보: F-01(미래지출 입력) 온보딩 이탈, F-05(결제수단 배분) 이후 실행 마찰(문제③) |
| 2 | 고객 데이터 수집 | 피드백·설문·인터뷰·채팅기록·지원로그·웹분석 등 다중 소스 확보 | 현재 보유: 뱅크샐러드 As-Is 실사용 캡처 12장·유저플로우 PDF, 시장 리서치, 민원 통계(🔵). **공백**: 4단계 AI Peer Review 리포트가 지적한 대로 실제 설문·인터뷰 데이터는 아직 없음 — Journey 검증 전 반드시 보강 필요 |
| 3 | 고객 페르소나 만들기 | 데이터 기반 가상 인물로 여정의 맥락을 부여 | 완료: 대표 4명(Core=이서연·Adjacent=정하늘·Extreme=신은서·Non-user=조민아) + 스펙트럼 분석 보고서 12명 |
| 4 | 핵심 단계 파악 | 인지~구매 후 등, 여정의 중요 단계를 정의 | **이 프로젝트 고유의 단계를 새로 정의해야 함** — 맨 아래 경고 참고. 후보 골격(확정 아님): 트리거 인지 → 미래지출 입력(F-01) → 보유카드 등록(F-02) → 계산 결과 확인(F-03·F-06) → 신규카드 비교(F-04) → 실행(전환/해지, F-05) → 재검토 |
| 5 | 접점 및 채널 결정 | 고객이 브랜드와 상호작용하는 위치·방법 파악 | 앱 UI, 마이데이터 연동 동의 화면, 계산 결과 알림, 카드사 콜센터(실행 단계에서의 외부 접점 — 문제③과 직결) |
| 6 | 감정과 고충 강조 | 단계별 감정 고조·하락과 문제점 식별 | 페르소나 카드에 이미 기록된 감정(조급함·번거로움·좌절감·회의감 등)을 각 단계에 재배치해 여정 곡선으로 시각화 |
| 7 | 여정 검증 | 실제 고객 또는 테스트로 맵의 정확성 확인 | 4단계 AI Peer Review(다중 관점 교차검증)는 가설 점검용 보완 수단일 뿐 — 최종 검증은 실제 사용자 인터뷰/테스트로 대체 불가 |
| 8 | 인사이트에 따라 조치 | 접점 강화, 리소스 재배치, 신규 기술 투자 등 실행 | 08(Value Proposition)·09(PRD) 작업에 여정에서 드러난 병목(F-05 실행 마찰 등)을 요구사항으로 반영 |

## 2. 고객 여정 매핑의 일반적인 과제 극복

| 과제 | 설명 | 이 프로젝트에서의 대응 |
| --- | --- | --- |
| 깨끗한 데이터 우선순위 지정 | 정확·오류 없는 데이터를 여러 소스에서 확보해야 실제 여정을 제대로 반영 | 설문·인터뷰·웹분석 등 데이터 소스를 정기적으로 점검하고, 추정(⚪)·가정(🟡) 항목은 표기를 유지한 채 검증 계획을 별도로 남김 |
| 과도한 단순화 방지 | 여정을 지나치게 단순화하면 핵심 고충·감정 순간을 놓침 | 페르소나 유형(Core/Adjacent/Extreme/Non-user)별로 여정을 따로 그리거나, 최소한 Extreme(신은서)의 실행 마찰 구간은 Core 여정과 분리해 별도 레이어로 표시 |
| 내부 운영에 집중 | 고객 여정만 보면 내부 병목·비효율을 놓칠 위험 | F-01~F-06 기능 설계(윤정 담당)·마이데이터 연동 제약(효진 결정, 2026-08-19 10:42)과 대조해 서비스 청사진 형태로도 점검 |
| 협력적인 팀 환경 조성 | 부서 간 협업 없이는 핵심 인사이트를 놓침 | 여정 맵 초안을 윤정(서비스/시스템 설계)·효진(PRD·검증)과 공유해 Value Chain·Value Proposition과의 정합성 확인 |
