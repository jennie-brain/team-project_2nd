# 페르소나 카드 (Contextual Rewriting) — 미래지출 결제설계 서비스

> **이전 버전 안내**: 이 문서는 2단계(Convergent Filtering) 산출물이었던 "페르소나 2차 평가 — 미래지출 결제설계 서비스"를 완전히 대체합니다. 12명 전체 프로필은 커밋 `a81d481`, 2단계 평가 근거는 커밋 `b3cdc7d`에서 확인 가능합니다.
>
> 3단계(Contextual Rewriting)에서는 2단계에서 선별한 대표 4명을 **우리 서비스 고유의 언어(F-01~F-06 기능, 전월실적·혜택한도·연회비, Payment Plan, JTBD 문장)로 다시 기술**해, PRD·Value Proposition 작업(08~09)에 바로 투입 가능한 카드로 만들었습니다.

## Core — 이서연

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 3개월 뒤 결혼하는 예비신부. 혼수·신혼여행 지출에 맞춰 카드 혜택을 놓치지 않고 싶다 |
| JTBD | 혼인이라는 소비 변화가 예정돼 있을 때, 나는 카드별 전월실적·혜택한도·연회비를 미리 계산해 최적의 결제조합을 짜고 싶다 — 그래야 신혼여행·혼수 지출에서 놓치는 혜택 없이 최대 혜택을 받을 수 있다 |
| 핵심 페인포인트 | 기존 서비스는 과거 소비 기준 단일 카드 추천에 그쳐, 아직 일어나지 않은 혼인 지출 변화를 반영하지 못함 (F-01 부재의 As-Is 공백) |
| 목표 | 결혼 준비 기간의 지출을 카드별로 배분해 Payment Plan을 확정하는 것 |
| 대표 발화 | "석 달 뒤에 신혼여행이랑 혼수 비용이 한꺼번에 나가는데, 지금 카드로 어디까지 커버되는지 아무도 안 알려줘요." |
| 관련 기능 | F-01(미래지출 입력)·F-02(보유카드 입력)·F-03(시나리오 계산)·F-04(신규카드 비교) 전 구간의 핵심 사용자 |
| 지표 연결 | Payment Plan Selection Rate의 1차 표적(Beachhead·SOM) 모집단 |

## Adjacent — 정하늘

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 이미 여러 장의 카드를 병행 사용 중인 카드 최적화 고관여 유저. 계산 자동화를 원한다 |
| JTBD | 여러 카드의 실적·한도를 매달 직접 추적해야 할 때, 나는 자동으로 계산된 결과를 받고 싶다 — 그래야 커뮤니티·스프레드시트에 쏟던 시간을 아낄 수 있다 |
| 핵심 페인포인트 | 서비스가 주려는 가치(카드 조합 최적화)를 이미 알고 실천 중이지만 전부 수작업이라 시간 비용이 큼 — F-03이 자동화하려는 계산을 사람이 직접 하고 있는 상태 |
| 목표 | 매달 반복하는 수작업 최적화를 서비스로 대체해 시간을 아끼는 것 |
| 대표 발화 | "저는 이미 카드 조합을 짜서 쓰고 있어요. 근데 매달 실적 계산을 엑셀로 다시 하는 게 너무 번거로워요." |
| 관련 기능 | F-03(시나리오 계산)의 자동화 가치를 가장 빠르게 체감할 사용자군 — Beachhead 이후 SAM 확장의 조기 전환 채널 |
| 지표 연결 | Q1(혼인) 검증 이후 SAM 확장 단계에서 전환 속도가 가장 빠를 것으로 예상되는 얼리어답터 채널 |

## Extreme — 신은서

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 계산상 해지가 유리한데도 실행에 3번 실패한 사용자 — "계산 결과만으론 부족하다"를 보여주는 경계 사례 |
| JTBD | 계산 결과로 해지가 유리하다는 걸 알게 됐을 때, 나는 그 결정을 끝까지 실행할 근거와 안내를 원한다 — 그래야 상담사 만류나 절차 복잡함에 다시 포기하지 않는다 |
| 핵심 페인포인트 | F-05가 "해지 대행"까지 나가면 실행 마찰(상담사 만류, 절차 복잡)을 서비스가 책임질 수 없는 약속이 됨 — 이미 팀이 F-05 스코프를 "판단 근거 + 유의사항 안내"로 좁힌 근거가 된 인물 |
| 목표 | 계산 결과를 실제 행동으로 옮기는 것 (단, 서비스가 해지 실행 자체를 대행하지는 않음) |
| 대표 발화 | "계산해보면 답이 나오는데, 막상 해지하려고 하면 상담사가 다른 카드를 권하고... 결국 그냥 뒀어요." |
| 관련 기능 | F-05(결제수단 배분 설계)·F-06(계산 근거 공개)의 스코프를 "안내"로 한정하게 만든 Guardrail G-04 직결 근거 |
| 지표 연결 | Payment Plan Selection Rate(선택률)와 별개로 "선택 후 실제 실행률"을 구분 추적해야 함을 시사하는 리스크 지표 |

## Non-user — 조민아

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 미래 소비를 예측·입력하는 것 자체를 신뢰하지 않는 잠재 비사용자 — MVP 핵심 가정이 실패할 조건을 보여줌 |
| JTBD (역질문) | 이 유형에겐 표준 JTBD가 성립하지 않음 — 대신 "무엇이 있어야 이 사람도 쓰게 될까"라는 역질문으로 접근해야 함 |
| 핵심 페인포인트 | F-01(미래지출 입력)의 전제 — "몇 달 뒤 소비를 스스로 예측할 수 있다" — 자체를 신뢰하지 않음. 유사 기능을 냈던 더쎈카드의 서비스 종료(원인 미확인)가 이 불신의 근거 |
| 목표(비목표) | 예측 대신 "그때그때 대응"으로 충분하다고 느낌 — 서비스의 핵심 가정과 정면으로 배치 |
| 대표 발화 | "몇 달 뒤에 얼마 쓸지 어떻게 알아요. 그냥 필요할 때 필요한 카드 쓰면 되는 거 아닌가요." |
| 관련 기능 | F-01 전제 자체에 대한 반증 사례 — 온보딩에 "과거 패턴 기반 초기값 자동 제안" 같은 완화장치가 필요함을 시사 |
| 지표 연결 | 온보딩(F-01) 단계 이탈률 — "가장 큰 가정"이 실제로 얼마나 흔들리는지 검증하는 선행 지표로 활용 |
