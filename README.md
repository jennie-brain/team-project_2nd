# team-project_2nd — 서비스 역기획 프로젝트

기준 서비스를 시장·기업·고객 관점에서 분석하고, 산업 경계를 넘어 문제 해결 메커니즘을 탐색·전이하여 실행 가능한 개선 PRD로 재구성하는 32시간 팀 프로젝트입니다.

> 역기획의 최종 목적은 기존 서비스의 숨겨진 정답을 복원하는 것이 아니라, 목표한 사용자 가치에서 필요한 기능·정책·데이터·운영 조건을 역산하여 더 나은 기획을 만드는 것입니다.

## 핵심 흐름 (5 Step)

1. **시장·기업·고객 분석** — 경쟁, 가치사슬, 성공 조건, 세그먼트와 고객 맥락 확인
2. **문제·기회 정의** — JTBD와 기회점수(OS)로 본질적 문제와 우선 기회 정의
3. **메커니즘 탐색** — 산업 경계를 넘어 같은 문제를 해결한 사례 탐색
4. **전이·믹스매치** — 가져올 원리, 바꿀 조건, 제외할 요소 구분
5. **개선 PRD 역산** — 실행에 필요한 요구사항·데이터·정책·검증 기준 작성

방법론별 세부 내용과 프로젝트 적용 방식은 [`방법론.md`](./방법론.md)에 정리되어 있습니다.

## 주제 선정 게이트 (7문항 중 6개 이상 `예`)

- [ ] 팀원이 직접 사용하거나 공식 화면·도움말·약관으로 주요 흐름을 확인할 수 있는가?
- [ ] 기준 서비스와 핵심 사용자 시나리오를 한 문장으로 제한할 수 있는가?
- [ ] 개선할 문제를 기능명이 아니라 사용자 목표와 장애물로 설명할 수 있는가?
- [ ] 동일·인접·교차 산업에서 참고할 문제 해결 사례를 찾을 가능성이 있는가?
- [ ] 32시간 안에 핵심 개선 기능 1개와 보조 기능 0~2개로 제한할 수 있는가?
- [ ] 필요한 데이터·정책·외부 연동·예외를 합리적인 수준에서 분석할 수 있는가?
- [ ] 성과지표와 해당 산업의 법·윤리·운영 리스크를 함께 논의할 수 있는가?

## 운영 원칙 (요약)

1. 하나의 기준 서비스는 깊게, 해결 사례는 넓게 탐색한다.
2. 기능의 외형이 아니라 작동 메커니즘을 가져온다.
3. 역산한 내부 구조를 사실처럼 단정하지 않는다 (Fact/Inference/Assumption 구분).
4. 시스템 분석은 개선안의 현실성을 확인하는 데 필요한 만큼만 한다.
5. 산업별 책임성과 제약을 마지막 체크리스트가 아니라 설계 조건으로 다룬다.
6. 많이 만드는 것보다 선택의 근거를 명확히 한다.
